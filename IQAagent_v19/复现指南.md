# 复现指南

本指南说明如何在干净环境中复现 IQAagent v0.19 的评测结果。

---

## 一、环境要求

| 项目 | 要求 |
|------|------|
| 操作系统 | Linux / WSL2（vLLM 服务端）；Windows 10/11 或 Linux（评测客户端） |
| Python | 3.10 或以上 |
| GPU | NVIDIA，≥ 18 GB 显存（Qwen2.5-VL-7B BF16；推荐 RTX 4090 24 GB） |
| CUDA | 12.1 或以上 |
| 模型权重 | Qwen2.5-VL-7B-Instruct（见下方获取方式） |

### 模型权重获取

模型权重已上传至百度网盘，直接下载后解压到任意目录即可：

- **百度网盘**：[Qwen2.5-VL-7B-Instruct](https://pan.baidu.com/s/1_uI7efZx6k6IqP7fsgPeKA?pwd=t84h)（提取码：t84h）

也可从以下公开渠道下载：

- HuggingFace：`Qwen/Qwen2.5-VL-7B-Instruct`
- ModelScope：`qwen/Qwen2.5-VL-7B-Instruct`

下载后记录模型所在路径（下文以 `/path/to/Qwen2.5-VL-7B-Instruct` 表示），在 vLLM 启动命令和评测命令中替换为实际路径。

解压后的代码目录结构如下：

```

├── pipeline.py                # 主评测管道

├── skills/                    # VLM 适配器 + Prompt
├── evaluation/

│   └── metrics.py             # SRCC / MAE 计算
```

## 四、数据集准备

### 4.1 KonIQ-10k 验证集

3. label 文件已包含在代码仓库：`data/koniq/koniq10k_val.csv`

### 4.2 SPAQ 测试集

## 五、启动 vLLM 推理服务

在 **GPU 机器**（Linux/WSL2）上执行。

### 5.1 KonIQ 和 SPAQ 统一启动命令

v0.19 的客户端在发送前已将图片缩到 512×512（262144 像素），服务端不需要额外的 `--mm-processor-kwargs`，KonIQ 和 SPAQ 使用同一套 vLLM 启动参数：

```bash
nohup python -m vllm.entrypoints.openai.api_server \
  --model /path/to/Qwen2.5-VL-7B-Instruct \
  --port 8000 \
  --max-model-len 4096 \
  --limit-mm-per-prompt '{"image": 4}' \
  > vllm.log 2>&1 &
```

等待约 60 秒，直到日志出现 `Application startup complete` 后再运行评测。

> **与 v0.18 的区别**：v0.18 需要在服务端用 `--mm-processor-kwargs '{"max_pixels": 602112}'` 限制 SPAQ 图片分辨率，否则 OOM 或截断。v0.19 将缩图逻辑移到客户端（`vlm_client.py`），服务端无需感知数据集差异。

## 六、运行评测

在**评测客户端**（可以是同一台机器或 Windows 本地）执行。将 `<SERVER_URL>` 替换为 vLLM 服务地址。

### 6.1 KonIQ-10k 验证集全量

```bash
python evaluation/run_eval.py \
  --dataset koniq \
  --vlm server \
  --base-url http://<SERVER_URL>:8000/v1 \
  --images-dir /data/koniq/images \
  --labels-csv data/koniq/koniq10k_val.csv \
  --label-min 1 --label-max 5 \
  --workers 3
```

预计运行时间：约 45 分钟（2015 张，3 workers）。

**v0.19 参考结果**（已记录在 `results/eval_koniq_20260728_144459.csv`）：

| 版本 | 样本数 | SRCC | MAE_100 | MAE_native（1–5 尺度） |
|:----:|:------:|:----:|:-------:|:---------------------:|
| v0.18 | 2015 | 0.6384 | 13.37 | 0.5348 |
| v0.19 | 2015 | 0.6709 | 19.89 | 0.7956 |

### 6.2 SPAQ 测试集全量

```bash
python evaluation/run_eval.py \
  --dataset spaq \
  --vlm server \
  --base-url http://<SERVER_URL>:8000/v1 \
  --images-dir /data/spaq/images \
  --labels-csv data/spaq/spaqTest.csv \
  --label-min 0 --label-max 10 \
  --workers 2
```

> **注意**：SPAQ 的 MOS 标签范围为 **0–10**（非 0–100），务必传入 `--label-max 10`，框架内部会自动换算。

**v0.19 参考结果**（已记录在 `results/eval_spaq_20260728_145350.csv`）：

| 版本 | 样本数 | SRCC | MAE_100 | MAE_native（0–10 尺度） |
|:----:|:------:|:----:|:-------:|:----------------------:|
| v0.19（50张） | 50 | 0.7989 | 13.27 | 1.327 |
| v0.19（全量） | 1125 | 0.7499 | 14.85 | 1.485 |

### 6.3 断点续跑

若评测中断，可用 `--resume` 从已有结果继续：

```bash
python evaluation/run_eval.py \
  --dataset koniq \
  --vlm server \
  --base-url http://<SERVER_URL>:8000/v1 \
  --images-dir /data/koniq/images \
  --labels-csv data/koniq/koniq10k_val.csv \
  --label-min 1 --label-max 5 \
  --resume results/eval_koniq_<已有文件>.csv \
  --output results/eval_koniq_full.csv \
  --workers 3
```

## 八、快速冒烟测试（3 张图）

正式全量评测前，先用 3 张图验证流程：

```bash
python evaluation/run_eval.py \
  --dataset koniq \
  --vlm server \
  --base-url http://<SERVER_URL>:8000/v1 \
  --images-dir /data/koniq/images \
  --labels-csv data/koniq/koniq10k_val.csv \
  --label-min 1 --label-max 5 \
  --limit 3
```

检查点：
- `status` 列全部为 `ok`（无 `error` / `missing`）
- `predicted_score_0_100` 不是整十倍数（五档分布融合在正常工作）
- `reasoning` 字段中无文件名或路径信息
- 终端输出显示 `SRCC=...`（非 `n/a`）

## 九、输出结果说明

结果保存在 `results/eval_<dataset>_<timestamp>.csv`，每行对应一张图片：

| 字段 | 说明 |
|------|------|
| `image_id` | 图片文件名 |
| `status` | `ok` / `error` / `missing` |
| `predicted_score_0_100` | 模型预测分（0–100） |
| `predicted_score_native` | 换算回数据集原生尺度的预测分 |
| `mos_native` | 数据集标注的 MOS（原生尺度） |
| `mos_0_100` | 换算至 0–100 的 MOS |
| `distortions` | 检测到的失真类型列表 |
| `reasoning` | VLM 推理说明 |
| `router_profile` | Router 使用的规则配置 |
| `evidence_anchor` | 工具层证据锚点分 |

终端最终输出：

```
================================================
Valid N    : 2015
SRCC       : 0.6384
MAE (0-100): 13.3704
MAE native : 0.5348
Saved      : results/eval_koniq_<timestamp>.csv
```

## 十、常见问题

**Q：vLLM 启动时报 `CUDA out of memory`**  
原因是模型权重加载后显存不足。确认 `nvidia-smi` 中没有残留进程（`kill -9 <pid>`），然后重启 vLLM。

**Q：SPAQ 评测 SRCC 只有 0.2–0.3**  
原因是使用了旧版（v0.18）框架，vLLM 对高分辨率图片视觉 token 进行了静默截断。v0.19 已在客户端（`vlm_client.py`）内置缩图逻辑（262144 像素上限），使用第五节的统一启动命令即可正常评测，不需要 `--mm-processor-kwargs`。

**Q：`image file not found` 错误**  
`--images-dir` 路径下找不到 CSV 中的文件名。检查图片目录是否正确，以及图片文件名是否与 CSV 中的 `img_id` / `image_id` 列一致。

**Q：`BRISQUE` 相关 warning**  
`piq` 库未安装或调用失败属于正常情况，Router 会自动重新归一化其余证据，不影响最终结果。安装方式：`pip install piq>=0.8`。
